# Contributing

One question decides what belongs here: *would a GTM engineer build a
go-to-market system out of this?* If yes, open a pull request.

## Add an entry

One line, in the section it fits, in this shape:

```markdown
- [Name](https://github.com/owner/repo) `LICENCE` — what it does for a GTM system, in one sentence.
```

In the pull request, say in a sentence why it earns a place.

## What gets merged

- **It is a real, maintained project.** A commit in the last 12 months, or
  a note in the entry saying it is quiet.
- **The licence tag is what the licence file says.** Open the file and
  check. If the project is source-available (n8n's Sustainable Use
  License, the Elastic License, a Business Source License) or keeps an
  enterprise directory under a commercial licence, the tag says so. Do not
  write "open source" for a licence the OSI has not approved.
- **The description is a fact, not a pitch.** No "best", "blazing",
  "revolutionary". No star counts; they go stale within weeks.
- **It is not already here** under another name. Check for renamed and
  moved repositories.

## What does not

- Closed-source products, however good. This list is for things you can
  read and run.
- Forks and rebrands of a project that is already listed.
- Tools whose purpose is to profile individual people across their
  personal accounts. Account and company research belongs here; that does
  not.
- Lists of prompts with no code, tests or structure behind them.

## Removing or correcting an entry

Projects get archived, relicensed and renamed. A pull request that fixes a
licence tag, replaces a dead link or removes an abandoned project is as
welcome as a new entry. Say what changed and link the evidence.

## Checks

A link checker runs on every pull request and once a week. A dead link
fails the check.
